阶段12 工程陈述候选抽取提示词 v30

任务：仅依据输入的 Evidence 及已确认来源上下文，产生 0 到多条可独立引用的候选 Engineering Statement。不得补充常识、猜测缺文或给出超出原文的工程建议。所有自然语言内容使用中文；JSON 字段名、枚举值和协议常量使用结构规范规定的值。

输入中的 `source_units` 是代码为覆盖对账划定的保守来源单元，每项形如 `{"source_unit_id":"...","source_text":"...","unit_kind":"complete|fragment"}`。它不是强制的 Statement 拆分边界。`complete` 与 `fragment` 都必须在顶层 `source_unit_coverage` 中恰好出现一次：
- `covered`：`candidate_indexes` 列出覆盖它的候选序号（从 1 开始）。一条 Statement 可以覆盖多个单元；一个单元只有在确实包含多个独立命题时才可对应多条 Statement。
- `excluded`：`candidate_indexes` 为空，并填写简短 `reason`。只有组织性标题、无法独立理解的残句、仅作上下文的文字、已由前一来源成员承载的续接片段、非工程内容或来源结构无法确认时才能排除。

输出必须是严格 JSON。每条候选在 `source_unit_ids` 列出它实际覆盖的来源单元。`status="ok"` 时至少有一条候选；只有所有单元均有可解释的排除处置时才返回 `status="no_statement"`、空候选和 `no_statement_reason`。

只允许下面列出的字段和形状。示例中的省略号表示实际字符串或数组内容，不是可输出字符；不要另造 `text`、`entity_role`、`candidate_index`、`total_steps`、`step_order`、`source_order`、`source_quote`、`source_context` 等别名：
```json
{
  "status": "ok",
  "candidates": [
    {
      "statement_text": "……",
      "statement_type": "fact|requirement|procedure|condition|observation|verification|limitation",
      "predicate": "requires|prohibits|describes|causes|verifies|limits_scope",
      "source_unit_ids": ["输入中已有的 source_unit_id"],
      "subject_entities": [{"surface_form": "必须逐字出现在 statement_text 中的实体", "role": "subject|object|related|quantity_target"}],
      "conditions": [{"surface_form": "必须逐字出现在 statement_text 中的前置条件"}],
      "applicability_scope": {"status": "unknown"}
    }
  ],
  "source_unit_coverage": [
    {"source_unit_id": "输入中已有的 source_unit_id", "status": "covered", "candidate_indexes": [1]}
  ]
}
```
无陈述时只能使用：`{"status":"no_statement","candidates":[],"no_statement_reason":"中文理由","source_unit_coverage":[{"source_unit_id":"输入ID","status":"excluded","candidate_indexes":[],"reason":"中文理由"}]}`。`covered` 项禁止 `reason`；`excluded` 项必须有 `reason`。`subject_entities` 和 `conditions` 中的成员必须是对象，不能直接写字符串。`conditions` 的每个对象只允许一个 `surface_form` 字段，严禁添加 `role`、`kind` 或其他字段；只有 `subject_entities` 才有 `role`。

只有输入确实给出对应已确认来源组时才添加以下可选字段，并严格使用输入给出的 ID 和序号：`procedure_group={"group_id":"……","status":"indexed|uncertain","step_index":1,"step_total":2}`，`source_list_item={"group_id":"……","status":"indexed|uncertain","item_index":1,"item_total":2}`，`source_question={"group_id":"……","status":"linked|uncertain","answer_option":"……","answer_text":"……"}`。`uncertain` 时用 `uncertainty_reason` 说明原因。只有已确认跨 Evidence 来源项的第一成员才能写 `supporting_evidence_ids`；否则完全省略该字段。

陈述粒度采用“最小完整回答单元”：
- 同一主体、同一适用范围下，动作与它的方法、直接结果、验收标准、阈值或必要目的保持一条，不得拆成失去上下文的微型陈述。例如“紧固件应拧紧，不得松动”是一个完整要求。
- 共同表达一个必需状态的并列属性保持一条。同一来源单元或同一来源列表项内，语义同构、只是对象不同的并列成分合为一条，并保留多个实体。
- 具有同一根因和最终结论的连续因果解释保留完整因果链，不同时生成包含关系的局部句和汇总句。
- 不同主体、可独立成立的动作或要求、不同适用条件、不同来源列表项，应分别形成 Statement。标点、换行和“、”“和”“及”不单独决定拆分。
- 拆分后每条都必须能独立理解。明确的代词、省略主体、总领句义务和已确认标题范围应在有来源支持时补入，不得自行猜测。

`predicate` 只表示整条 Statement 的主要粗粒度关系，不要为了让一条 Statement 只有一个 `predicate` 而拆散完整语义。义务、阈值和前提要求用 `requires`；明确禁止用 `prohibits`；事实、定义和普通操作描述用 `describes`；明确因果用 `causes`；真正的核验结果用 `verifies`；适用或排除边界用 `limits_scope`。

语义和来源要求：
- `statement_text` 保留主体、动作、必要条件、适用范围、数值、单位、比较方向、否定、规范强度和因果方向。不得把“应”“宜”“可”“不得”互相替换，不得改变上下限。
- `subject_entities` 只收录工程对象、设备部件、责任主体和数值目标；每个 `surface_form` 必须是 `statement_text` 的准确子串。数字、单位、动作和普通属性不单独当作实体。
- `conditions` 只表示真实的准入或成立前置条件，且文字必须是 `statement_text` 的准确子串。因果前件不因出现“若”“当”就自动填入 `conditions`。
- `applicability_scope` 只有在当前 Evidence 或已确认标题明确支持时才使用 `known`；`applicability_text` 必须同时是 `statement_text` 中的连续原文片段，以及当前 Evidence 或已确认标题中的连续原文片段，不能只挂字段而从陈述正文省略，也不能概括、改写或扩大范围；否则使用 `{"status":"unknown"}`。
- 数量、单位、比较、模态、否定和关系方向由适配器从候选正文派生，不返回 `object_value`、`value`、`unit`、`quantities`、`normative_modality`、`negation_scope` 或 `relation_direction`。

来源结构：
- `operation_group_context` 只用于已确认的有序操作。完整并已定位的步骤使用 `procedure_group` 的给定 `group_id`、`status="indexed"`、实际序号和总数；来源不完整时使用 `uncertain` 并说明原因。
- `related_source_context` 中的分类、要求和活动列表使用 `source_list_item`；列表序号只是来源定位，不是操作顺序。已确认的题干与印刷答案使用 `source_question`。
- 对 `group_kind="question_options"`、`source_review_status="confirmed"` 且 `answer_marked=true` 的来源组，只由 `stem_evidence_id` 指向的首个题干 Evidence 产出题组候选。`question_extraction_guidance` 是数组；逐项读取其中的 `role` 与 `resolved_statement_support`。优先使用 `role="stem"` 数组项给出的已核答案代入结果；多个空缺要按题干顺序分别代入答案分项，不要求分隔后的答案仍以连续原串出现在正文中。候选不得保留问号、空括号或选项标记。`source_question` 必须逐项使用该来源组给出的 `group_id`、`answer_option` 和 `answer_text`；若答案来自另一 Evidence，则把给出的 `answer_evidence_id` 放入 `supporting_evidence_ids`。`role="support_only"` 只表示该题组的答案或选项文字不重复生成题组 Statement；仍须检查当前 Evidence 的其他 `source_units`，其中的独立命题照常提取。只有全部来源单元均有明确排除依据时，才能返回 `no_statement`。
- 一个已确认来源项跨多个 Evidence 时，只在第一成员产出候选，其余成员放入 `supporting_evidence_ids`。标题和无关相邻 Evidence 不得当作直接支持。

返回前进行三项对照：每个 `source_unit` 均有且只有一个覆盖处置；每条候选均可回到它声明的来源单元；候选之间无重复、无遗漏、无凭空增加。只返回 JSON，不输出解释文字。
