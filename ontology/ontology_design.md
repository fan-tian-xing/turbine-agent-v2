本体描述跨书籍复用的对象、活动及允许的知识连接。书籍、版本、章节和页码属于 Evidence 来源；某次处理哪一章由导入配置决定。

## 分类与 Mention 处理

- “凝汽器壳体现场组装”改成凝汽器、壳体、组装三个相关对象／活动提及；现场条件保存在 Statement，不为每台设备生成一套活动类。
- “凝汽器冷却管、空冷管束”等组合名称按通用部件种类和设备上下文表达。查冷却管要求时，需同时核对属于哪种设备和什么作业。
- v11 根据已审查原文补充19个直接影响检索的对象及试验类：汽轮机汽缸、垫铁、管道、排汽管道、阀门、安全阀、疏水器、空冷散热器、散热翅片、水位计、水位调节装置、水位报警装置、高压加热器满水保护系统、凝汽器胶球清洗装置、直接空冷装置、间接空冷装置、严密性试验、灌水查漏试验、风压查漏试验。定义与适用边界见注册表，来源为 DL/T 5190.3—2019 对应条款。
- 本轮不新增基础、平台、栏杆、板件或验收文件类；保留 Mention、来源名称和所属设备上下文。平底、支撑方式、材料等先作为适用条件，不能丢掉。
- 不把案例、条件、量值和公式建为业务类。来源提及、类代理、知识记录、来源证据和资料记录属于独立存储合同；当前最简抽取把条件与数值保留在知识记录的完整文字中。

“暂未建类”不等于替换成一个含义更宽的同义词。例如“平底箱罐”不会作为“箱罐”的别名直接入词典。来源名称与平底条件仍保留，未确认的映射由 Evidence 全文召回。

## Statement 与 Evidence

Evidence 保存可独立理解和引用的原文上下文及唯一来源定位。Statement 使用现有字段保存完整断言、原始 Mention、语义角色和 Evidence 支持；本体映射由现有实体映射字段和图谱关系维护。条件、数值、比较词和单位留在断言文字中；多个独立要求分别表示。标题、表头和注释作为上下文，不强造事实。

| Statement 内容 | 用途 |
| --- | --- |
| 知识类型、断言 | 区分要求、检查、步骤、措施等检索意图；保持来源含义。 |
| 对象／活动提及、本体类、角色 | 建立查询入口，区分主对象、配合对象和相关设备。 |
| 完整断言中的条件、数值与单位 | 供回答模型结合完整 Evidence 判断适用性；当前不强迫模型另拆字段。 |
| Evidence 与支持成员 | 取回完整来源，核验每条断言。 |

本体升级优先重新计算实体映射并重建派生投影，不改变 Statement 的原文和 Mention；只有发现原文语义缺失时，才回到 Evidence 局部重抽。

不独立抽取“应、宜、不得”字段；断言和 Evidence 保留这些措辞及否定含义。未知名称只内嵌于 Statement，不创建术语节点。数据记录类型在 `record_types` 中声明，不能冒充本体业务类；输入中的 `Mention` 仅表示来源提及，不建立图节点。

## 关系与查询

| 关系 | 连接对象 | 规则 |
| --- | --- | --- |
| 子类属于 | 类与父类 | 本体审定的种类关系，连接到事物。 |
| 实例属于 | 有明确身份的对象／活动与类 | 不从书籍泛称推断现场实例。 |
| 组成 | 部分与整体 | 须有原文支持；种类之间的组成不等于实际设备归属。 |
| 具有要求、作业、异常、检查、原因、措施、验证 | 适用对象／活动或有关知识记录与 Statement | 由知识类型、对象角色及明确来源决定。 |
| 包含步骤、步骤先后 | 程序 Statement 与步骤 Statement、步骤与步骤 | 只表达来源明确的程序归属或执行顺序。 |
| 依据来源 | Statement 与 Evidence | 工程事实通过这一关系取回来源。 |

查询识别对象、活动和意图后，用规范名或审定别名定位类；按受控关系查 Statement，同时在 Neo4j 的 Evidence 全文索引补充召回。泛部件命中还须核对设备上下文，不能将所有壳体的要求混用。向回答模型返回完整 Evidence、出处及 Statement 的精简对象角色上下文。数值问题从已读原文中定位条件和限值，核对来源后由程序比较，临时计算信息不写回图谱；最终显示建议和依据来源。

OWL 表达业务类层次；SHACL 和注册表检查关系方向、端点类型与记录结构。程序校验不证明工程事实正确，仍须对照传入 Evidence 核对断言中的条件、数值和原意。

## 首批验收问题

这些题验证本体与检索能力，不是本体适用范围。

- 制造厂未规定试验压力时，压力容器严密性水压试验采用工作压力的1.20倍是否符合要求？
- 同样前提下，1.30倍是否满足试验压力要求？
- 凝汽器壳体现场组装时，每米弯曲度偏差4 mm是否符合要求？
- 凝汽器壳体全长度弯曲20 mm是否符合要求？
- 凝汽器冷却管穿装受阻时应该怎么办？

初始样本来自 DL/T 5190.3—2019 第五章物理37—38页；跨页条款须带齐续文。检索问题里的数值只用于当次判断，不写成资料事实。

## 合同版本

机器版本由完整注册表内容计算指纹；项目只维护当前本体和当前知识。修改本体后，使用导入入口的 `--remap` 重新映射已有资料，不调用模型或重抽 Statement。原始名称和角色保存在 entities，类别与来源绑定使用现有映射字段；Statement ID 保持不变。`core.ttl` 与 `shapes.ttl` 由 `OntologyRegistry.authority()` 生成，SHACL 结构若未变化可保持原文件。

## 扩展准则

新书优先复用已有类与关系。新增类应具有稳定含义，并解决真实的对象区分或查询需要；不用“设备×活动×条件”的组合不断造类。新增关系须明确两端、方向和来源规则。改别名通常不重抽；改变类含义、关系或所需结构时，只复核受影响记录与查询。资料新版按条款变化更新相关 Evidence 和 Statement。旧映射与派生关系在成功更新后替换，不保留图谱副本。

## 核对过的公开定义代码

- [IOF Core.rdf](https://raw.githubusercontent.com/iofoundry/ontology/master/core/Core.rdf)：核对了 `PieceOfEquipment`、`MaterialComponent`、`ActionSpecification` 和组成属性。其设备、部件区分包含角色语义；本项目采用设备与部件不互斥、组成与种类分开的原则，未复制其完整上层推理体系，也不声明形式等价。
- [ZORRO linkml.yaml](https://github.com/kai-vu/zorro/blob/main/linkml.yaml)：核对了 Component、Procedure、Step 和 part_of、consist_of、involve 的实际定义。借鉴对象、程序、步骤分开连接的方式；本项目通过 Statement 记录程序及步骤，并保持来源支持。
